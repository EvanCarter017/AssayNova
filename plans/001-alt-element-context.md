## Implementation requirements

### 1. Make development mode explicit and isolated
Enable development tools only when --watch is present AND NODE_ENV is not production. Normal node server.mjs and NODE_ENV=production node server.mjs --watch must not inject any picker scripts/metadata, expose source metadata, serve dev modules, or start the dev watcher/events.
Store all new browser modules outside dist/. Serve them through a fixed, explicit /__dev/ allowlist; never accept an arbitrary source filesystem path from a URL.
Preserve GET/HEAD behavior, existing static routes, CSP, loopback binding, and live-reload semantics. Dev route read errors must return a response instead of crashing the server.
Verify syntax and HTTP in both modes; use test ports, not 4317.

### 2. Provide honest source hints without editing application source
In watch mode only, annotate served HTML opening tags with source-file and original 1-based line information, generated from dist/index.html. Do not write annotated HTML to disk. Use an HTML-aware scanner or equivalent that respects quoted > characters, comments, doctype, and script/style raw text. Preserve original text, scripts, SVG structure, and existing attributes. No npm dependencies.
Provide a development-only metadata endpoint with project root and verified dynamic template hints based on the actual dist/app.js function definitions. Known-view selectors above can locate the active dialog renderer. Label renderer hints as function-level hints, not exact element-line mappings. If a mapping cannot be established, say so; do not invent framework component names or source locations.
Static selections should point to the original HTML file/line. Dynamic dialog selections should prefer the real renderer hint instead of misleadingly attributing every child to the HTML dialog shell.
Any source context helpers should be side-effect-free and independently testable.

### 3. Implement Alt + left-click selection
Load the picker from dev-client.js only in development.
- Holding Alt arms selection. Moving over a target outlines it and shows a compact element label/help. Alt+left click captures the actual clicked element (including nested text spans/icons/SVG); include the nearest actionable ancestor separately.
- Capture relevant pointer/mouse click events before normal handlers so Alt-clicking Submit a sample, a link, report-open control, or a form control does not perform the underlying action. Only the Alt+left-click gesture is intercepted; ordinary interactions and right-click remain unchanged.
- Release Alt, Escape, window blur, or pointer cancellation clears the selection state and outline. Avoid stuck modifier state or interfering with Ctrl/Meta keyboard combinations. Prevent the native Alt menu where appropriate.
- Keep the tool visually absent except while selecting or showing copy feedback. Use an isolated Shadow DOM UI with pointer-transparent outline; tool UI must not be picked recursively.
- Work inside the existing native modal dialog as well as on the page. Account for native dialog top-layer/inert behavior so feedback/fallback controls are visible and usable.
- Keep outline positioning correct on scroll/resize and clean up listeners on page lifecycle as needed.

### 4. Capture bounded useful context
Include:
- Sanitized page address/route (no credentials or query values), query key names if useful.
- Project root, target tag/id/classes/role/accessible label, and a stable unique CSS selector; verify selector uniqueness before claiming it.
- Nearest actionable ancestor, short ancestor/breadcrumb path, nearest main section heading.
- Viewport width/height, device pixel ratio, scroll offset, and target bounding rectangle.
- Source hints and their precision (exact original HTML tag line vs verified renderer-level hint vs unavailable).
- A compact sanitized HTML excerpt (bounded around 1200 characters), bounded visible text, and a focused computed-style snapshot (typography, colors, layout, spacing, border).
- A bounded set of matching stylesheet selectors/declarations and stylesheet paths. Report matching rules honestly: cascade may override them. Handle media/supports rules and inaccessible stylesheets without throwing.
Do not collect input values, textarea content, selected option values, contenteditable content, passwords, cookies, localStorage/sessionStorage, network logs, entire-page HTML, or unrelated data. Strip development annotations from the HTML excerpt. No telemetry or external request.
Independent read-only review clarification: saved request values are also rendered as ordinary heading/table/definition text in dist/app.js:128 and 152–153. Redact these known request-derived regions consistently in snippets, labels, section headings, breadcrumbs, and attribute values; input-only filtering is insufficient. Do not read storage to discover those values.
Dynamic view source hints must take precedence over annotations copied into that view: reportChart() at dist/app.js:110–111 clones the annotated static hero SVG into the report, so its copied HTML line does not describe the report renderer.
The tool must continue to function if a context field is unavailable.

### 5. Build the predefined Chinese Prompt and copy it

【希望修改的内容：请在这里填写】
All other sections and constraints are filled automatically, including:
- The selected element and source/route information.
- The structured, bounded context above, marked explicitly as quoted data, not instructions.
- Default boundaries: make the smallest change around the target and directly related styles/components; preserve other layout, brand assets, business behavior, sample/demo notices, and accessibility unless the user's requested change explicitly says otherwise.
- Re-find the element in current source before editing; selectors/coordinates may drift.
- Follow improve plan + execute for substantive changes: plan, separate executor, reviewer checks. For trivial edits keep the plan small.
- Keep development tooling out of production. Do not deploy, publish, or introduce dependencies unless the user's request requires it.
- Verify the relevant page at desktop/mobile and the affected interaction, then describe actual changes/tests.
No extra blank fields for the user to fill.
Call clipboard.writeText from the user gesture, without waiting for a network request to retrieve context. Preload metadata asynchronously; if it has not arrived, use honest limited hints.
Show success only after copy succeeds. Clipboard rejection/unavailable API must show a usable manual-copy panel with the full preset prompt and copy/select controls. Do not falsely claim success.
