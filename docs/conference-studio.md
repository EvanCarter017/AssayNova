# AssayNova Admin · Reports

`/admin` is the foundation of the AssayNova management backend. Reports is its first working module: select a product/photo, compose a report, review the portrait preview and open published snapshots. The admin shell remains when generated data are later archived. A password-only server-side gate protects the local admin. Production TLS/access policies, roles, orders, customer management and permanent storage infrastructure remain deferred; there are no usernames, registration or unused management screens.

The current report generator produces synthetic examples, not instrument measurements. That context is visible in the private Reports workspace and private provenance only. Newly generated customer report pages and PDFs keep the ordinary customer COA experience. The two existing static sample reports retain their disclosures.

## Start the integrated local admin

Use the existing bundled Node 20+ and Python runtime. There are no dependencies to install or source files to build. From the checkout containing this implementation:

```powershell
Set-Location D:\Projects\assaynova
.\conference\start.ps1 -PublicOrigin 'http://192.168.0.60:4318'
```

Open `http://127.0.0.1:4317/admin`. On first use, the administrator chooses the password directly in that page; the assistant does not choose or enter the real credential. Later visits require that password. This helper starts the local server with `--watch --port=4317 --conference-reports --admin`; it does not choose another port, kill an existing listener or start 4320. If 4317 is occupied, deliberately stop the verified project-owned local instance first. Before the first handoff from the previous standalone generator, stop its verified 4320 process too: only one admin/generator process may write a store at a time. Do not stop unrelated listeners. Later restarts preserve every existing snapshot.

Equivalent explicit launch:

```powershell
& 'C:\Users\Administrator\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe' server.mjs --watch --port=4317 --conference-reports --admin --admin-public-origin=http://192.168.0.60:4318
```

Run the separate LAN preview with an explicit admin bridge to the same primary process:

```powershell
& 'C:\Users\Administrator\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe' server.mjs --host=0.0.0.0 --port=4318 --conference-reports --admin-proxy=http://127.0.0.1:4317 --admin-proxy-origin=http://192.168.0.60:4318
```

Use the machine's actual LAN address for both public origin and bridge origin. After local first setup, open `http://192.168.0.60:4318/admin` and enter the same administrator password. The password page is English; authenticated Reports retains its English/中文 choice. Customer navigation has no admin links. The bridge forwards only `/admin` to the fixed loopback primary; 4317 remains the sole report writer and password/session authority. LAN first-password setup is blocked. Bridge cookies use the 4318 name and are remapped to the primary name internally, so bridge login/logout does not replace or revoke a distinct 4317 browser session. Restarting 4317 invalidates all its sessions, including bridged sessions.

Both proxy flags are required together, with `--conference-reports`, a literal wildcard/private IPv4 bind, nonproduction mode, and no `--admin` or `--watch`. The upstream must be canonical `http://127.0.0.1:<different-port>` and the external origin must be a canonical private IPv4 HTTP origin on the listener port. DNS, public addresses, credentials and URL paths are refused. Only the configured LAN Host and `127.0.0.1:4318` are accepted; peers must be loopback/private IPv4. A mutation needs its exact external Origin before rewriting, and forwarded identity headers are ignored. Request bodies remain bounded to 8 KiB except exact canonical import-chunk PUT routes, capped at 256 KiB; the bridge has 10-second incoming request/header bounds and a 60-second upstream inactivity limit. Passwords and cookies are never logged. This HTTP configuration is for a trusted private LAN preview; production TLS and access policies remain future work.

Without both proxy flags, the LAN `/admin` namespace returns 404 for all methods. To disable LAN administration, restart only the verified LAN process without those flags, keeping its reader enabled. The primary `--admin` still requires `--conference-reports`, refuses production and binds other than `127.0.0.1` or `::1`. IPv6 local usage may use `--host=::1`, with `http://[::1]:4317/admin`; the LAN bridge specifically requires an IPv4 primary. The password/session gate is not the future production authorization system.

`--admin-images=ABSOLUTE_DIRECTORY` chooses the read-only source folder. The default remains `C:\Users\Administrator\Desktop\COAs_西林瓶图片_按品名剂量`. Its 219 original PNGs become 110 selectable products by grouping terminal ` (NN)` duplicates and preferring the unsuffixed photo. No bulk images are copied into Git or `dist`. `--conference-store=ABSOLUTE_DIRECTORY` selects the existing store for both the public reader and local admin. The helper accepts equivalent `-Images` and `-Store` arguments. Credential storage is separate: default `work/admin-auth/credential.json`, or `--admin-auth-store=ABSOLUTE_DIRECTORY` / helper `-AuthStore`. Never point QA at the real credential directory.

## Reports workflow

Choose one saved **Customer** before searching for products. The initial profile is VialCove for the supplied default image directory, or Research Client for a custom image directory. Names printed on English reports use 1–64 printable ASCII characters. **Upload folder / SKU table** is the customer-management UI: its browser pickers select files on the browser device and upload managed copies to the server. Choose **New customer**, enter its name, then select a picture folder and table; choose **Selected customer** to replace or update that customer's imported collection. There is no manual absolute-path form or server-folder picker.

An existing version-1 registry with `customers: []` is a deliberate empty workspace and remains empty across restart. Only a missing registry file retains the original initial-seed behavior. **No customers yet** keeps customer/product selection and generation disabled while the new-customer name, folder/table pickers, language, report history and logout remain available. The importer selects **New customer** until the first import is confirmed; confirmation selects that saved customer, enables **Selected customer** and makes its products searchable without reloading. No placeholder customer or empty-ID catalog lookup is created.

Temporarily removing a seeded customer is a separate guarded owner-maintenance action, not a delete button in this UI. With the verified primary idle and stopped, retain the exact original `customers/profiles.json` bytes privately under `<report-store>/customers/archives/`, together with their SHA and an operation journal, before atomically removing only the intended customer ID from the active array. Preserve other customers, all reports/previews and authentication storage. An archived name can be used for a new active import. Restoring an old directory-backed profile also requires a compatible source directory and product/image name mapping; if a later operation renames original pictures to short codes, restore the appropriate mapping or filenames too. The metadata archive alone is not a one-click image migration or recovery feature.

The private versioned registry is `<report-store>/customers/profiles.json`, outside published snapshots. Existing server-directory customers remain compatible without migration: their original full-name PNGs, such as `BPC-157 10mg.png`, remain read only and use the unchanged directory scanner. Selection, **Reload products**, image retrieval and generation still check that customer's collection. If an old directory is missing, empty or unusable, generation stays disabled; select that customer and upload a replacement picture folder/table, or reload after its source becomes available again. Sign-in and upload controls remain usable. The legacy server-directory backend API is retained for compatibility, but has no visible path-editing form. A corrupt registry is never silently replaced.

Customer and product IDs are paired on the server, including private image URLs. The report’s client name comes from the saved customer; free-text client overrides are rejected. Choosing another customer or confirming an import affects the next generation and preserves every previous preview, published report, Lookup Code and downloaded image snapshot. Local and LAN Admin use this same primary configuration. Managed imports move with the report store. Legacy absolute paths may need owner-side rebinding through the compatibility API or replacement through browser upload after moving to a later server. Launch and authentication settings remain unchanged; deployment/runtime portability is a separate task.

1. Use **Create report** to choose a saved customer and search/select its product, then review the full report preview. Composition uses the selected catalog defaults automatically; there are no manual recipe inputs. Blends split on spaced ` + ` so NAD+ remains intact. KLOW 80mg uses GHK-Cu 50 / BPC-157 10 / TB-500 10 / KPV 10 mg. GLOW 70mg uses GHK-Cu 50 / BPC-157 10 / TB-500 10 mg, confirmed from its photo.
2. Optionally enter lot, received/reported dates and replicate purity overrides. Lot accepts printable ASCII, maximum 40 characters; the customer name comes from the saved profile. Dates are real `YYYY-MM-DD`, reported on or after received. Purity accepts 99.05–99.95 with at most two decimals. Recipes preserve mg, ml and IU, with no IU-to-mg conversion. Nominal content is separate from HPLC normalized area. Automatic replicate purity shares a per-report baseline; net content varies within ±2%.
3. **Preview only** creates a private unpublished snapshot. Customer lookup cannot find its code and Copy LC/customer-link controls stay hidden. **Generate & publish** generates a new independently randomized immutable snapshot and a fresh LC; it does not promote an earlier preview. Product/form/history controls lock while generating. Errors preserve the prior successful result.
4. Review the published portrait preview, copy its LC, open the normal customer report and download PDF. Partners use ordinary Verify COA. New publication can be queried without refreshing an already open customer page. Direct links, refresh, browser history and copy actions use the stable snapshot.
5. The **Saved reports** library has **Published reports** and **Removed reports** views. Open a row to review its saved snapshot. **Remove report** asks you to confirm the exact product and Lookup Code before stopping public lookup, PDF downloads and QR report links. The original files remain available privately to administrators. **Restore report** confirms the same identity and restores public access using the original code and files. Cancel or Escape before confirmation makes no change. A pending change locks generation and library actions; an interrupted response offers the same safe retry, or Cancel followed by Refresh to check the saved state. An uncertain change clears that report's current preview and customer actions; unrelated previews stay open. If the change is acknowledged but refreshing the library fails, the status retains both the completed change and the library error until Refresh succeeds. It is a private admin list; there is no customer enumeration endpoint.

## Browser folder and table imports

Name imported pictures with the short code: **ADA10.png ↔ ADA10 ↔ Adamax 10mg**. Choose a picture folder and an XLSX, UTF-8 CSV or TSV table. Select the sheet and header row, then map the two required columns **Short code / SKU** and **Full product name**. Use optional **Dose** when the name and specification are separate; `10mg*10vials` means 10 mg per vial. There is no image-column or per-row picture selector, and no analyte/dose inference from SKU characters. Full names need a clear dose/unit boundary; explicitly known labels also accept normalized spelling.

Preview retains every mapped source row and all valid pictures, including unresolved identities, duplicate short codes and unused images. A nonempty table can be confirmed even with zero ready products; blocked rows remain red, unavailable for report generation and editable through **Manage products**. Unique short codes with the same full product name keep separate row IDs and pictures. No nearest-product/dose inference is performed. See [partial catalogs and manual correction](catalog-corrections.md) for merge rules, provenance, corrections and retry behavior.

Uploads use sequential chunks of at most 256 KiB. Limits remain 500 retained images, 8 MiB per file/table, 512 MiB per image pool, four pending jobs and one parser. Pending uploads now retain a persisted seven-day idle lease. Actual image bytes must decode as PNG, JPEG or WebP, at most 20 megapixels; normalized PNGs must also fit the limits. Workbook limits are unchanged: 128 ZIP members, 16 MiB expanded, 4 MiB per member, 16 sheets, 10,000 rows, 64 columns, 100,000 cells and 2,048 characters per cell. Formula/ambiguous-merge source errors remain blocked until deliberate full identity review. Price columns are not imported.

Pending jobs can be explicitly resumed after login or refresh, restoring uploaded files, offsets, mapping and prepared preview. Cancellation preserves the active catalog; a commit in progress cannot report successful cancellation. Confirmation and corrections write immutable validated revisions and durable completion receipts before staging cleanup. Lost responses and restarts can safely retry without duplicate customers or rollback. Customer registry activation is atomic and revision-guarded. Existing published report snapshots and legacy directory readers remain unchanged. Moving the report store requires carrying its registry, revisions/assets and receipts together. This change does not deploy a domain or change authentication/report-runtime portability.

## Existing directory products and bundled search aliases

Search accepts a canonical name or substring, an exact quote SKU (such as `TR10`, `BC10`, `SM10`, `G5k`), or an explicitly mapped family (`TR`, `RT`, `SM`, `BC`, `BB`). Case, fullwidth text, spaces and common dash variants are normalized. Plus signs and DAC / No DAC / Acetate identities remain meaningful. Full SKUs are exact: `SM2` cannot select SM20, `TR100` cannot select TR10, and H10 cannot select HGH 24/40 IU. Optional unit suffixes are accepted only when the quoted code's numeric dose and actual product unit agree.

Family TR / RT includes the original 5mg photo variants. The quote has no TR5 or RT5 SKU, so those exact codes return no result. BC includes only single BPC-157 products; BB includes only the existing two-component BPC-157 + TB-500 combinations (BB10 = 5+5, BB20 = 10+10, BB30 = 15+15 mg). KS includes only Kisspeptin-10 5mg; OT only Oxytocin Acetate 2mg. Generic Kisspeptin 10mg and plain Oxytocin 10mg remain searchable by their canonical names and do not inherit those aliases. No generic G family is inferred from the conflicting HCG/HMG prefix.

Controlled search spellings include BPC157, TB500 with its quote description, GHK-CU, AHK-CU, AOD9604, ARA290, LL37, IGF-1LR3, the source typo Cagriliintide, the long KPV name and HGH191AA(Somatropin). These search equivalents do not rename report chemistry. KLOW80, GLOW70, TI and CP10 map only to their reviewed existing compositions. Numeric/standalone codes such as 375, PMF, HN, PEG and 5AD use explicit entries rather than loose digit matching.

The price-free curated map covers **107 of 202 quote rows / exact SKUs**, targeting **106 of the 110 original-photo products**. Family/name metadata cover 108 products, including the two unquoted 5mg variants. The remaining two products retain canonical-name search. Of the **95 excluded quote rows**, 42 have no exact dose/photo and 43 have no matching canonical product/photo. The remaining 10 are deliberately excluded: BBG70 (two-component description contradicts GLOW), KS10 (unconfirmed Kisspeptin-10 identity), two H15 rows (duplicate/unavailable 15 IU), MT-2 (name says Melanotan I), CS5 / TR20-RT40 / RET60 (unsupported blends), CS10 (contradictory 2.5+2.5 versus total 10mg and no matching photo), and the backtick SKU. Missing doses never select the nearest available product.

Only canonical names, SKU/family/search aliases and source-row references are maintained in the server-side `conference/product-aliases.json`; no prices, workbook paths, full workbook or runtime spreadsheet parser are included. The browser receives additive private alias metadata and the allowlisted `/admin/product-search.mjs` module. The alias JSON itself has no HTTP route.

The canonical selected product appears in a compact summary below search results. A unique match can select itself; multiple matches preserve an already valid selection or prompt for a choice. Changing selection updates the canonical product and its automatic defaults; no results clear selection and disable generation. There is no separate selected-product image preview. The right panel shows the full COA after Preview or Generate, including its original product photo. That separately labelled last generated report remains immutable when product search changes; searching does not automatically generate reports.

## Routes, storage and security

All admin shell assets, session/history/generation APIs, source-photo URLs and private preview/download URLs live under `/admin/`. Legacy global `/api/session`, `/api/history`, `/api/generate`, `/images` and `/bundles` do not open them. Both integrated hosting and the optional compatibility host share one `conference/admin.mjs` handler and the same existing catalog/store implementation.

The compatibility host remains available for isolated tests or an intentional separate local session: `node conference/studio.mjs`, open `http://127.0.0.1:4320/admin` (root redirects there). It is not part of the normal startup workflow and must not run alongside integrated admin against the same store. Its CLI image/store/public-origin options are unchanged; its HTTP routes use the canonical `/admin` namespace.

The primary handler checks loopback peers and exact Host/Origin before authentication; the bridge validates its external boundary first, then forwards to that unchanged handler. Only the password page and its minimal login assets are available before unlock; operator scripts/styles, search module, import module, catalog/session/history/generation/import APIs, original photos and private previews/downloads return 401 without a valid server-side session. A per-run ASCII-hex token remains required for generation, imports and logout. JSON remains limited to 8 KiB; only exact import-chunk PUT routes accept octet-stream bodies up to 256 KiB. No CORS, canonical paths and realpath-contained assets remain enforced. Both hosts retain 10-second request/header limits; the renderer has its existing 45-second bound. The token is never logged or saved. This is a password-only management foundation without accounts or production access policies.

The default `work/report-studio` store remains ignored and outside `dist`. No migration or regeneration is performed. Published `AN-9563-6F4E` and every other existing LC keep their same PDF/SVG/JSON bytes. Published folders contain public `bundle.json`, `report.pdf`, `report.svg` plus private `private.json` (seed, synthetic provenance and operator inputs). Previews remain private. Removal atomically renames a complete `published/<LC>` directory to the sibling `removed/<LC>` directory; restoration reverses that rename. All snapshot bytes, including private metadata, are preserved across restart. Removed codes stay reserved and cannot be allocated to another report. There is no permanent-delete action or automatic removal. The two built-in sample reports cannot be removed. A job publishes only after complete outputs; generation, removal and restoration share one writer lock. Catalog staging uses the seven-day retention and explicit resume policy described above; report-generation staging is unchanged.

The public reader serves only `published`: `GET/HEAD /__reports/AN-XXXX-XXXX`, its `report.pdf`/`report.svg` children and the canonical QR PDF URL `/coa/AN-XXXX-XXXX/report.pdf` return 404 while a report is removed. It remains enabled only by `--conference-reports`, with no public listing or writes. Fresh generated-code lookup and direct/back/forward navigation recheck publication before displaying fields or download/copy actions. There is no polling, and files already downloaded or requests already in flight cannot be recalled. DTOs contain only approved report/transcript fields and same-origin public asset URLs. Original photo paths, private provenance, token and seed stay excluded. Admin route prefixes are added to response URLs without modifying stored bundles.

The authenticated mutations are exact `POST /admin/api/reports/<LC>/remove` and `/restore` routes with an empty JSON object, the existing same-origin session and run token, and the same 8 KiB body limit. `GET/HEAD` never changes report state. The plain `/admin/api/history` array remains published-only; the exact `?state=removed` filter returns the same row shape for removed snapshots. Authenticated PDF/SVG previews use `/admin/bundles/removed/<LC>/report.pdf` or `report.svg`; these paths are never public customer links. Moving or backing up the report store must include the removed directory to preserve recovery and code reservations. The existing single-process writer ownership requirement remains in force.

The renderer contract and one-page portrait A4 master are unchanged: bundled Python `-B conference/render_report.py --request ABSJSON --output ABSDIR`, writing `report.pdf`, `report.svg`, `bundle.json`. Unsupported chemistry remains unassigned representative data; no verified theoretical identity is invented, and unperformed screens remain Not assessed.

## Administrator password and sessions

After login, the language selector in Reports switches between English and 中文 immediately. The password page is always English and has no language selector, regardless of the saved Reports language or browser language. It translates only admin controls and messages. Product names, entered values, LC, dates, units and saved COA/PDF/SVG contents stay unchanged. Switching does not reload, refetch, generate a report, change the selection or discard the current preview; it also works during an in-flight operation.

An explicit choice in Reports stores only `en` or `zh-CN` under the browser key `assaynova.admin.locale.v1`. The password page neither reads nor writes that preference. Without a valid saved value, a Chinese browser language selects Chinese, otherwise English. If browser storage is blocked, Reports still switches in memory; a fresh password page remains English. No password, session token or form values are stored by the language feature. The exact static `/admin/admin-i18n.mjs` module is allowed before login; other private scripts, APIs, photos and downloads remain protected.

The first password is user-owned and entered only in the local `/admin` page. It must be 10–128 characters and at most 512 UTF-8 bytes; there are no composition rules and its exact text, including spaces, is preserved. No plaintext password is written, logged, placed in a URL or saved in browser storage. The ignored credential file stores only version, random salt and a 32-byte scrypt hash. The fixed native configuration is N=16384, r=8, p=5 with a 64 MiB memory bound; it is not supplied by the credential record. See [Node 20 crypto](https://nodejs.org/docs/latest-v20.x/api/crypto.html#cryptoscryptpassword-salt-keylen-options-callback) and [OWASP password storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html#scrypt).

Setup and login require a per-run CSRF challenge and same-origin JSON requests. One shared in-flight password operation bounds hashing across both routes; excess requests receive 429. Five incorrect attempts impose a 60-second cooldown with Retry-After. Only a missing credential file permits setup. Invalid, partial, oversized or unreadable records fail closed with 503; setup never overwrites them. Exclusive file creation protects the first password from concurrent setup, with mode 0600 where the filesystem honors it.

Successful unlock issues a fresh random opaque cookie: HttpOnly, SameSite=Strict, Path=/admin, port-scoped name, and Secure when hosted over HTTPS. The credential itself is not in the cookie. Sessions live only in server memory, with an 8-hour absolute limit and 30-minute idle limit. Valid requests update idle activity. Expired sessions are purged and at most 32 sessions are retained. **Log out** immediately revokes that cookie; a process restart invalidates every old session while preserving the password. The operator redirects expired API requests back to the password page. See [OWASP session management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html).

Report storage and credential storage are independent. Archiving generated reports must not delete `work/admin-auth`, and closing `/admin` does not clear its password. There is no password reset/recovery API. If the local owner must recover a forgotten password or corrupt record, stop the verified admin process first, verify the absolute credential-file path, and archive only that exact `credential.json` outside its auth directory. Restart and let the owner choose the replacement password directly in `/admin`. Do not perform recovery while an admin process is running, do not archive the whole `work` directory, and do not clear report folders or browser drafts. No recovery or cleanup is performed by this change.

## Checks and shutdown

```powershell
$env:ASSAYNOVA_CATALOG_QA='1'
& 'C:\Users\Administrator\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe' --test tests/*.test.mjs
Remove-Item Env:\ASSAYNOVA_CATALOG_QA
& 'C:\Users\Administrator\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' -B tests/conference-renderer.test.py
```

Tests use disposable stores and random local ports, including actual integrated Python generation and restart persistence. Native QA checks `/admin`, search, generation, private history, customer lookup/PDF/copy, desktop/mobile layouts and console state. No live report needs regeneration to test the mount.

Stop the local admin with Ctrl+C. Restart local 4317 without `--admin` to close the admin namespace; retain `--conference-reports` if customer lookup should continue. Stopping the admin does not remove published reports. To disable generated customer lookup too, deliberately restart the relevant customer server without `--conference-reports`.

If generated data are no longer needed, first stop the one writer and archive only the verified exact report-store directory. Clearing that data does not remove `/admin` or future management modules. Inspect the resolved absolute store path before any later deletion. Never remove `work` wholesale, browser drafts/localStorage, original product photos, static samples or future real data. No destructive cleanup is performed by this change.
