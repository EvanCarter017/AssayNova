# Retained catalog records in administration

Import preview lists **retained / ready / needs correction** counts. A table-only new customer and an all-blocked set of source rows can be confirmed. Confirmation sends the exact `previewId`; it does not silently discard problem rows or select a neighboring product image. A disabled idle button uses the normal unavailable cursor. Upload/read/confirm work alone sets `aria-busy`; requests have bounded timeouts and release their operation state in `finally`.

The Reports product chooser uses the existing ready-product search unchanged, with a precedence check for exact non-held blocked SKUs. The browser uses the same SKU-key normalization as import matching: NFKC, case folding, normalized dashes, then removal of spaces and hyphens. A blocked literal SKU such as `ADA10mg` therefore also reserves `ADA-10mg`, rather than allowing a unit-qualified fallback to select another product. Held entries stay visible but release their SKU reservation. Problem entries appear only as disabled red options in this existing chooser, beginning with **Content missing · unavailable** / **内容缺失 · 无法选择**, followed by SKU and product name. The text remains visible at narrow widths and carries the unavailable meaning independently of color. There is no adjacent problem-card list. Only ready products can become the current report selection; unrelated incomplete entries do not disable manual selection or generation for a ready product. Version 2 generation requests include the current `catalogRevision`; legacy requests retain their previous shape. Ready v2 option labels include SKU and full name so distinct SKUs sharing a name remain distinguishable.

**Resolve issues (N)** / **处理异常（N）** opens a native dialog outside the import and report forms. Its count covers every incomplete entry in the selected customer/brand, independently of the product search. The dialog title and introduction explicitly name that brand, and the initial filter shows only entries needing correction. All retained records remain reachable through the All / Ready filters, search and pagination. A brand without issues has a clear empty state. The original mapped source values and sheet/row provenance are read only. Administrators can review the SKU, full product name, per-vial dose, Hold state and image. Save deliberately submits all three identity fields and Hold so the backend can distinguish a complete manual source review from an image-only correction. An incomplete correction is saved but stays unavailable until server validation passes. A successful ready correction refreshes the main chooser and whole-brand issue count while preserving another valid current product selection.

The labelled **Brand** / **品牌** selector inside the dialog lists only saved profiles from the current session. These are the existing customer profiles used as brand collections; no new customer-to-brand relationship or schema is introduced. A successful authenticated brand read keeps the dialog open, updates the main customer chooser once, clears the previous product selection even when product IDs or SKUs are shared, resets the editor, source values, related records, images, selected File, query and pagination, and starts with the new brand's blocked filter. The next selected record loads only that brand's image pool and revision. The main product chooser asks for an explicit choice after the switch. Changing the main customer or session externally still closes the dialog and invalidates pending reads.

Unsaved identity, Hold, explicit image selection/removal or new File changes require an inline confirmation before a brand read starts. **Keep editing** receives initial focus; it and Escape cancel the proposed switch while retaining every edit and preview. **Discard changes and switch** starts the read, but the old form remains available if that read fails. A failed read preserves the current brand, list, filters, selection, File and preview, with a localized retry control. The selector stays on the current brand until the read succeeds. An active catalog operation, unresolved save receipt, pending image upload or incomplete upload cleanup disables brand switching with a recovery message. Selecting another entry or closing/reopening cannot bypass an unresolved save; its exact retry receipt remains retained. Ordinary Escape outside the confirmation still closes the dialog.

Image selection is explicit: keep the current image, select an already retained image, upload a replacement, or remove it. PNG/JPEG/WebP uploads are bounded to 8 MiB, sent in 256 KiB chunks through a correction-purpose upload job, then referenced by opaque job/file IDs. Before the first create request, the browser freezes a cryptographically random 32-hex `uploadIntent` for that file/target/revision. A lost create acknowledgement retries the identical intent, allowing the server to return the original job before applying quota checks. Clearing or closing an unknown create reconciles that same intent and then cancels its job, even if the first request never reached the server. Failed chunk acknowledgements retain the job and reconcile its actual offset with GET before retrying, avoiding duplicate bytes and repeated job allocation. Clearing, replacing, switching entry or closing releases unused jobs with bounded DELETE retries. If a busy or unavailable connection prevents cleanup, the exact intent/job remains tracked for **Retry image upload cleanup**; a new upload waits for those unused jobs to be released. Late creation responses from an obsolete operation clean their known job without reviving its UI. Local previews use `FileReader` data URLs within the existing `img-src 'self' data:` policy. No blob CSP allowance, server path input, nearest-image inference or automatic image reassignment is added.

Each save uses `expectedRevision`. A catalog-revision 409 preserves typed values and the selected File. Upload quota/busy errors keep their upload-specific recovery messages. **Read latest version** loads the server record while keeping the previous edits in memory for deliberate restoration. If a PATCH response is interrupted, the controller retains its exact frozen request and image job reference in memory, including across dialog close/reopen; it never deletes an image job that may have been committed. Retry reuses the same request so the server can return its durable receipt. Upload failure does not convert a replacement-image save into a metadata-only save. Closing the dialog, changing customer/token or a newer action invalidates old UI responses. Escape closes the dialog and restores focus to the opener, or Manage products if the old opener was replaced.

Both the main administration language selector and the dialog selector use the existing English/Chinese locale setting. Switching language updates labels/reasons, source-row captions and the empty-image option without resetting form inputs, selected Files, selected assets or focus. The dialog uses a two-column desktop layout and a stacked layout below 700 px, with 44 px controls and scrolling for narrow screens.

Previously uploaded ordinary import jobs are discovered with GET and are never automatically activated. An administrator explicitly chooses a job to restore its mapping and preview. A job for another existing customer requires selecting that customer first. Successful confirmation or cancellation removes that job from the visible pending list immediately. Correction-purpose jobs are excluded from this ordinary import picker. The browser does not persist credentials, edits, product files or raw source values to storage; only the pre-existing locale preference is persisted.

Focused automated checks exercise the actual import controller, correction controller and operator integration against synthetic API adapters: partial/all-blocked confirmation, preview tokens, pending resume, modal saves, chunk boundaries, immutable raw values, revision conflicts, locale/File retention, interrupted responses, late-response guards, search precedence, and access to more than 500 records. Brand-switch checks cover identical SKUs/image filenames and shared product IDs across profiles, dirty confirmation and Escape, failed reads and retry, close/session/FileReader races, unresolved-save/upload locks, and ready/empty catalogs. Desktop/mobile appearance and native dialog keyboard behavior require native browser verification in addition to these checks.
